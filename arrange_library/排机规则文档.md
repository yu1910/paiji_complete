## 概述

排机规则用于优化基因测序实验中的文库分配，确保测序质量和效率。规则分为固定规则和可变规则两类，涵盖文库标签分类、优先级排序、数据量校验、文库混排、Index查重、碱基不均衡处理、Pooling系统调整等多个方面。

## 文库标签分类规则

### 标识类规则
**规则类型**: 固定规则
**用途**: 文库成Lane后的标识，与排机规则无关

**标识规则**:
- 标识类标签仅用于文库测序完成后的数据处理
- 不参与排机逻辑判断
- 作为后续数据分析的分类标签

### 文库拆分规则
**规则类型**: 固定规则（2026-04-24按当前代码口径更新）

**拆分模式区分**:
- **1.1模式（兼容旧名1.0，手工/常规产线 S）**：不参与自动预拆分。
- **3.6T-NEW 模式（自动产线 Z/ZS）**：仅在该模式下执行自动预拆分，按单 Index / 多 Index 固定阈值判断。

**拆分判定条件（仅 3.6T-NEW 模式适用）**:
1. **包Lane / 包FC / 指定 Lane / 指定 FC / 指定 Run 文库**：保持原有指定，不拆分。
2. **阈值计算**：
   - 单 Index 文库：合同数据量 `> 100G` 触发拆分。
   - 多 Index 文库：合同数据量 `> 300G` 触发拆分。
3. **触发拆分**：当合同数据量严格大于对应阈值，且满足自动产线条件时，判定为“需拆分”；等于阈值不拆分。
4. **拆分方式**：按阈值计算最小份数后向上取 2 的幂次，优先保持对半拆分思想；拆分后的每条子文库需要 `>2G`，除数据量、拆分标记、片段标识等字段外，其他业务字段保持一致。

**拆分影响**:
- 1.1/1.0 模式文库：不自动预拆分。
- 3.6T-NEW 单 Index 文库：`>100G` 自动预拆分。
- 3.6T-NEW 多 Index 文库：`>300G` 自动预拆分。
- 拆分后的子文库会携带 `wkissplit=yes`、原始总合同量和片段编号，用于后续排机与明细输出。

### 特殊处理标签
**规则类型**: 固定规则

需要单独组合处理的标签:
- **包Lane与否**: 指定文库是否独立成Lane
- **Lane ID**: 指定Lane编号，相同编号文库排同一Lane
- **FC编号**: Flow Cell编号，相同FC编号组成Run
- **RunCycle编号**: 测序参数备注，相同RunCycle排同一Lane
- **上机备注**: 特殊需求说明

**组合规则**:
- 相同编号的文库排在同一条Lane上
- 相同编号成Lane
- 相同FC成Run

### 版号规则
**规则类型**: 可打破的固定规则
- 相同版号的文库尽量排在同一Lane中
- 在满足其他约束条件下优先考虑版号一致性

### 包Lane前置校验补充
**规则类型**: 固定规则（以 `arrange_library_model6.py` 当前实现为准）  
**补充说明**:
- **适用对象**：仅对带包Lane编号的Lane执行专项校验。
- **有效数据量要求**：包Lane校验口径不是 `975G±10G`，而是 **有效数据量 `1000G±0.01G`**。
  - 有效数据量 = 合同数据量合计 + 显式平衡数据量。
  - 若Lane中已经混入AI平衡文库，则不再额外叠加显式平衡数据量。
- **Index对数要求**：整条包Lane的 Index 对数必须 **≥ 5对**。
- **Index冲突要求**：包Lane必须通过 Index 重复校验，存在冲突即判失败。
- **校验时机**：排机完成后会再次复核所有包Lane，不满足条件的Lane会被记录为规则错误。

**说明**:
- 文档中其他位置若出现 `975G±10G` 的包Lane口径，均以本节 `1000G±0.01G` 为准。
- 包Lane规则是专项红线，独立于普通 AI Lane 的通用容量窗口。

## 优先级排机规则

### 数据类型优先级
**规则类型**: 固定规则

**优先级分类**:
用于筛选通道和检验的文库，按数据类型标签分类：
- **优先级1 - 临检**: 最高优先级
- **优先级2 - YC**: 中等优先级
- **优先级3 - S级客户**: 特殊客户优先级
- **优先级4 - 交付临近**: 时间紧急优先级
- **其他**: 普通优先级

### 优先级1：临检文库排机规则

**文库标识**:
- **文库编码前4位**: FDYE、FDYT、FDYG、FDYP、FDYK、FDYX、FICR、FIPM
- **国际临检**: 英国临检文库首字母为E，美国临检文库首字母为C

**排机流程**:
1. **优先生成临检Lane**: 优先将临检文库生成N条完整Lane，进入排机池
2. **不足一条Lane时的补充策略**:
   - 优先补充"其他"池子的DHE、DHG文库（"其他"指非临检及YC，剩余全部为其他）
   - 其次按顺序补充手工诺禾碱基均衡文库：按校准后交付时间排序
3. **剩余处理**: 补充文库后，仍有剩余的临检文库不够一条Lane，则留在文库池等待下次排机
4. **大小数据量混排**: 临检文库大于70G和小于70G的文库排机规则相同，且可以同Lane排机

**同优先级排序**: 按下单时间升序

### 优先级2：YC文库排机规则

**文库标识**:
- **文库编码前4位**: FKDL
- **子项目名称**: 带YC标识的文库

**大数据量定义**: 单个index合同数据量 > 70G的文库

**排机流程**:
1. **优先处理碱基不均衡大数据量**: 优先挑出碱基不均衡的大数据量文库，按照排机规则生成整N条Lane。
2. **不足Lane时的补充**: 以当前档位的碱基均衡大数据量文库补齐，优先生成整N条Lane。
3. **剔除至整数Lane**: 补充后仍不够整N条Lane时，按优先级从低到高、数据量从小到大的顺序剔除。
4. **文库拆分**: 被剔除的大数据量文库可拆分为小数据量文库。
5. **小数据量排机**: 拆分后的小数据量文库，再按碱基不均衡优先、碱基均衡次之的顺序进入后续排机。

**补充说明**:
- YC档位作为高优先级档位，优先保证整Lane消化。
- 细粒度补量、剔除和拆分过程，以当前代码与配置实现为准。

**同优先级排序**: 按下单时间升序

### 优先级3：S级客户排机规则

**文库标识**:
- **项目名称**: 带SJ标识
- **识别方式**: 以当前业务标记和系统识别结果为准

**大数据量定义**: 合同数据量 > 70G的文库

**排机流程**:
1. **优先处理碱基不均衡大数据量**: 优先挑出碱基不均衡的大数据量文库，按照排机规则生成整N条Lane。
2. **不足Lane时的补充**: 以当前档位的碱基均衡大数据量文库补齐，优先生成整N条Lane。
3. **剔除至整数Lane**: 补充后仍不够整N条Lane时，按优先级从低到高、数据量从小到大的顺序剔除。
4. **文库拆分**: 被剔除的大数据量文库可拆分为小数据量文库。
5. **小数据量排机**: 拆分后的小数据量文库，再按碱基不均衡优先、碱基均衡次之的顺序进入后续排机。

**补充说明**:
- 同板文库可按同板优先原则处理。
- 更细的人工干预、界面来源或运营侧优先顺序，不作为本文档固定规则，实际执行以系统实现和业务操作规范为准。

**同优先级排序**: 按下单时间升序

### 优先级4：交付临近排机规则

**排序规则**: 按校准后交付时间升序

**规则说明**: 根据临近交付时间规则表计算，确保临近交付时间的文库优先排机

### 时间优先级
**规则类型**: 固定规则

**排序规则**:
1. **下单时间**: 越早下单越优先排机
2. **交付时间**: 离当前时间越近越优先排机（校准后交付时间）
3. **样本编码**: 包含扣减时间规则的样本优先处理

**说明**:
- 本节描述的是优先级排序方向。
- 若系统实际采用综合评分或多阶段筛选，以代码实现结果为准。

### 大数据量与小数据量文库定义

**大数据量文库**:
- **YC文库**: 单个index合同数据量 > 70G
- **S级客户文库**: 合同数据量 > 70G
- **临检文库**: 大于70G与小于70G可同Lane排机

**小数据量文库**:
- 合同数据量 ≤ 70G的文库
- 拆分后的文库（要求单个文库数据量 > 2G）

**拆分规则**:
- 大数据量文库拆分成小数据量文库
- 拆分后单个文库数据量必须 > 2G
- 小数据量从大到小排序进行排机

### 1.0新模式筛选规则
**规则类型**: 固定规则（自动线特有）

**筛选条件**:
1. **数据来源**：子项目名称中不得出现“药企”“医检所”“医学”“YC”“SJ”等关键词。
2. **文库类型限制**：排除外显子文库、HI-C文库、10X HD 系列文库、10X ATAC 文库。
3. **包Lane/FC/拆分限制**：不可已有包Lane、包FC或“需拆分”标签（仅限非需拆分样本）。
4. **备注限制**：加测备注或上机备注中含“加测”“混合”或“**不参与新模式排机**”的文库不参加 1.0 模式。
5. **建库结果**：诺禾文库需为“正常建库”，客户文库需通过“库检合格”；诺禾若样本编号中带 **H**（表示混库）也不参与 1.0 模式。
6. **Index对数**：诺禾文库若 Index 对数=1 且合同数据量 >150G，必须排除。
7. **拆分状态**：标记为“需拆分样本”的文库统一排除出 1.0 模式。

### 1.0模式排机流程
**规则类型**: 固定规则

1. **优先级**：样本编号包含 “ras” 的文库按 RNA 优先处理，其余可混排文库作为后续补充。
2. **板号限制**：同一 Run 中板号数量按当前模式规则控制，并优先保持同板集中。
3. **交付时间调整**：交付时间较近的文库在该模式下提升优先级。
4. **Lane容量**：
   - RNA 专用 Lane：上限 **2175G ±5G**。
   - 混排 Lane：上限 **2100G ±5G**。
5. **即时校验**：每生成一条 Lane 后必须立即执行规则复核（容量、Index 冲突、占比等），不合规立即回退重排。
6. **Index 定义补充**：Index 序列中，分号“;”左右分别代表 P7/P5；逗号“,”分隔多对 Index，可用于统计 Index 对数与判断单端/双端。

### 3.6T-NEW 模式排机规则
**规则类型**: 固定规则（适用于自动线/新模式，以 `arrange_library_model6.py` 当前实现为准）

1. **Lane容量口径**：当前代码中的普通 3.6T-NEW 调度目标上限不是文档旧版常写的 975G，而是按统一容量选择逻辑控制；其中全局目标上限常量为 **1100G**，有效上限为 **1105G**。最终是否合规以代码中的容量选择与校验结果为准。
2. **非包AI Lane Index对数下限**：仅在 **3.6T-NEW** 上下文中，非包Lane的 AI Lane 必须满足 **Index对数 ≥ 5对**；低于 5 对直接判为不合规。
3. **高优先级首轮预消耗机制**：代码存在“1.1之前先做一轮3.6T-NEW高优预消耗”的实现，用于优先消化临检/YC/SJ 等高优文库。
   - 单条预消耗Lane的目标保底量为 **995G**。
   - 单条Lane从1.1普通池借补位文库的上限为 **250G**。
   - 多条预消耗Lane并行时，临检分组数占比上限为 **60%**，避免临检过度挤占窗口。
4. **1.1与3.6T-NEW并存处理**：若系统检测到“3.6T-NEW预消耗Lane”和“1.1 Lane”同时存在，则最终收口阶段会保留已成Lane的1.1结果，不再做全局优先级硬回收。
5. **大池时效保护**：代码对高成本救援流程设有跳过阈值，优先保证主流程产出：
   - 已有1.1 Lane落地且未分配池 **≥1000个** 或 **≥4000G** 时，跳过后续高成本救援。
   - 当前 0 条Lane 成功且未分配池 **≥300个** 时，跳过零Lane高成本救援。
   - 未分配池 **≥1500个** 或 **≥18000G** 时，跳过大池高成本救援。
6. **校验方式**：排完每条 3.6T-NEW Lane 后，仍需做容量、Index冲突、Index对数、混排约束等即时校验；未通过则回退重排。

**说明**:
- 旧文档中“3.6T-NEW Lane统一按975G±10G理解”的表述不再准确，当前应以代码的容量选择函数和实际校验逻辑为准。
- `10+24` 测序策略另有专项规则，见下文补充章节。

## Index重复校验

### Index重复校验规则 (规则3)
**规则类型**: 固定规则，同算法
**目的**: 确保一条Lane中的Index序列不重复，保证后期数据拆分

**规则说明**:
- 纯算法规则，要确保一条lane中的index序列不重复，不然后期无法拆分数据
- 按静态数据区分Index重复校验规则（正向/反向）
- Index是建库过程引入的用来区分文库的标签
- 通过为每个样本添加不同的Index，可在单次测序中同时处理多个样本
- 测序完成后，通过识别Index序列将混合数据按样本拆分，生成独立的测序文件
- Index有双端index和单端index，按照碱基个数又分成6碱基、7碱基、8碱基以及10碱基
- 为了能最保证拆分，排机时需要校验index序列是否重复，保证至少有两位碱基不同，即可拆分开来
- 例如：6和8碱基最多可重复4位，8和8碱基最多可重复6个均可同lane上机

#### P7P5 Index查重规则
1. **P7端校验**: 当前文库Index与Lane中其他所有文库Index的P7端进行两两比对
   - 6碱基Index：重复不超过4位
   - 7碱基Index：重复不超过5位（2024年11月21日补充）
   - 8碱基Index：重复不超过6位  
   - 大于8碱基Index：重复不超过7位

2. **PE转接头重复**: 当前Index的P7端等于PE且比对的另一个Index的P7端也等于PE时，算PE转接头重复

3. **P5端校验**: P7超过固定重复位时需校验P5端
   - 如果P5端等于通用接头，比对组合中P5端也等于通用接头的，算重复
   - 如果P5端等于随机INDEX/RANDOM PRIMERS，算重复
   - P5端校验规则与P7端相同

#### P7 Index查重规则
- 仅校验P7端
- 重复位数限制与P7P5规则相同：
  - 6碱基Index：重复不超过4位
  - 7碱基Index：重复不超过5位（2024年11月21日补充）
  - 8碱基Index：重复不超过6位
  - 大于8碱基Index：重复不超过7位

### 10碱基Index文库数据量比例 (规则4)
**规则类型**: 固定规则，同算法
**数据来源**: 实验经验总结

**限制条件**:
- a、Lane中只含10碱基文库时，不做限制
- b、Lane中只含非10碱基文库时，也不做限制  
- c、Lane中含10碱基和非10碱基时，10碱基Index的文库数据量 > 40%（非10碱基文库数据量 < 60%）

**定义**: 
- 10碱基是指index序列字段碱基数是10个的文库
- 10碱基Index：包括单端和双端
- 仅看Index P7端长度
- 示例：10碱基index：AAAGGGCCTT; AAAGGG     6碱基index：AAAGGG; AAAGGGCCTT
- 一个文库含多index的，包含10碱基index则该文库数据量都算作10碱基的数据量
- 如：文库数据量为10G，该文库同时含有6、8、10碱基index，则算作10碱基index数据量为10G（仅看IndexP7端长度）

### 单端Index文库数据量比例 (规则5)
**规则类型**: 固定规则，同算法
**数据来源**: 实验总结值

**限制条件**:
- a、Lane中全部都是单端Index，不限制比例
- b、Lane中同时排有单端Index的文库和双端Index的文库，限制单端Index文库的合同数据量占整条Lane文库合同数据量 < 30%

**定义**: Index序列只有P7端没有P5端称为单端Index（Index序列字段没有";"存在的）

### 加测文库比例限制
**规则类型**: 固定规则  
**内容**: 同一条 Lane 中，加测文库的合同数据量占比必须 ≤ 25% 且允许额外 10G 缓冲。当 Lane 中出现超额时需回退并重新组合。

### 10+24 测序策略专项规则
**规则类型**: 固定规则（代码已有实现，旧文档缺失）

当 Lane 的测序策略命中 `10+24` 时，按专项规则单独校验：
1. **命中口径**：优先读取 Lane 元数据中的 `seq_strategy`，若文库自身的 `seq_strategy` 或 `current_seq_mode` 命中 `10+24` 也视为命中。
2. **Index对数要求**：整条 Lane 的 Index 对数必须 **≥ 5对**。
3. **Index冲突要求**：整条 Lane 不允许存在 Index 重复冲突。
4. **有效数据量要求**：按 **1000±5G** 校验，且口径包含平衡量：
   - 有效数据量 = 合同数据量合计 + 显式平衡数据量。
   - 若Lane中已存在AI平衡文库，则不再重复叠加显式平衡量。
5. **10碱基补平衡约束**：`10+24` 专项场景还要求补平衡占比与测序策略保持一致，代码常量中配置的平衡比例为 **5%**。

**说明**:
- `10+24` Lane 属于专项规则，不直接套用普通包Lane或普通 3.6T-NEW Lane 的全部口径。
- 当 `10+24` 专项规则与普通规则冲突时，以专项规则优先。

**分组基本原则**:

- **严格执行数据量占比**：分组表中的数据量占比（如0.8/0.99/1.0等）为强约束，必须严格执行，不得放宽或临时调整。

  - 示例：Lane容量975G、占比0.8，则碱基不均衡目标量780G，`wkbalancedata=195G`。
  - 填写口径：该字段按Lane维度填写，同一条Lane内每个文库该字段值必须一致。
- **有效容量修正**：若 `wkbalancedata` 在调度期被记为 0 或缺失，代码在后续会按上下文修正，避免低估有效容量。
- **规则边界说明**：分组表属于当前业务规则口径；若与代码中的兼容性校验结果冲突，以代码校验结果为准。

## Pooling系统规则

### Pooling调整规则
**规则类型**: 可变规则
**更新频率**: 每月1次调整

**调整原因**:
- 合同数据量与真实产出存在差异
- 需要对合同数据量进行人为系数调整

**调整方式**:
- 人工调整，总结过去1个月某类文库产出与合同数据量的差异
- 给相应文库及其合同区间给定系数

### Pooling系数计算
**规则类型**: 固定规则

**计算公式**:
- **下单量 = 合同量 × Pooling系数**

**单样本限制**:
- **最小下单量**: ≥ 1G
- **下单数据量 - 合同数据量**: < 30G

**Lane级别限制**:
- **Lane总下单数据量 / Lane总合同数据量**: < 115%

## 产出评判标准

### 有效合同总量
**目标**: 值 ≥ 合同数据量，越接近越好
**说明**: 衡量排机效果的核心指标，确保满足合同数据量要求

### 真实产率
**目标**: ≥ 1，越接近1越好
**计算公式**: 真实产率 = 实际产出量 / 预期产出量
**说明**: 衡量测序产出效率的指标

### 溢出比
**目标**: 越接近0越好
**计算公式**: 溢出比 = (测序产出量 - 有效产出量) / 合同数据量
**说明**: 衡量数据浪费程度，越低越经济

### 产出稳定性指标
- **全部样本真实产率趋近1**
- **CV值 < 1.15**（lane总下单数据量/lane总合同数据量），最大误差15%以内，越小越好

### B.2 统一Lane校验入口（`_validate_lane_state`）

`_validate_lane_state` 负责把不同Lane类型路由到不同校验分支，执行顺序如下：

1. 识别Lane上下文（包Lane / 10+24 / 专用不均衡 / 普通混排 / 3.6T-NEW）。
2. 执行最新Index规则校验（覆盖旧校验器冲突结果）。
3. 执行 `wkspecialsplits` 规则校验（A/B/EMPTY/OTHER）。
4. 执行57混排规则校验（按Lane语义分包Lane和普通Lane）。
5. 执行容量区间校验（支持平衡预留扣减后的有效容量）。
6. 包Lane分支追加执行包Lane三条硬规则。
7. 10+24分支追加执行10+24三条硬规则。
8. 3.6T-NEW非包Lane分支追加执行最小Index对数规则。
9. 汇总校验结果并返回，失败原因用于后续剔除/救援策略。

### B.3 候选Lane构建逻辑（`_attempt_build_lane_from_pool`）

核心是“增量加入-快速校验-择优保留”的循环：

1. 初始化空候选Lane与容量窗口。
2. 从候选池按排序键取下一个文库尝试加入。
3. 每次尝试加入后，先执行快速失败检查：
   - 是否触发优先级门禁；
   - 是否超容量上限；
   - special split 是否非法；
   - 57组合是否非法；
   - 最新Index快检是否冲突。
4. 快速失败则回退该文库，继续尝试下一个文库。
5. 当达到最小容量后，进入“候选终选”阶段：
   - 优先保留更接近不均衡目标占比（35%）的方案；
   - 同时比较容量贴合度与稳定性。
6. 结束时对候选Lane执行完整严格校验，成功则成Lane，失败则整组回退。

### B.4 救援构建差异

#### 1）`_attempt_build_rescue_lane_from_pool`
- 目标是“小范围快速成Lane”，容错更偏向时效；
- 对候选池规模、尝试次数和回退策略有额外收敛控制；
- 失败不影响已成Lane，仅回流未分配池。

#### 2）`_attempt_build_lane_from_prioritized_pool`
- 同时使用“优先回收池 + 未分配池”构建；
- 优先消化高优库，必要时再引入低优补量；
- 仍受全局优先级门禁约束，不能跨越当前放开档位。

### B.5 容量规则细化（`_resolve_lane_capacity_selection` / `_resolve_lane_capacity_limits`）

1. 容量计算分三层：机型基础容量 -> 规则码容量窗口 -> 平衡预留修正后的有效窗口。
2. 机型基础参考值（配置口径）：
   - Nova X-10B：`380G`，容忍 `±10G`；
   - Nova X-25B：`975G`，容忍 `±5G`。
3. 命中特定规则码（`tj_1595_standard_pe150_25b`、`tj_1595_standard_pe150_25b_other`）时，执行硬封顶：
   - 目标上限 `<=1100.0G`（`SCHEDULING_MAX_TARGET_CAP_GB`）；
   - 有效上限 `<=1105.0G`（`SCHEDULING_MAX_EFFECTIVE_CAP_GB`）。
4. 平衡预留修正：
   - 包Lane按绝对量预留；
   - 专用不均衡Lane按比例预留；
   - 修正后窗口再用于最终合法性判定。
5. 10+24专项固定窗口：以 `1000G` 为目标，容忍 `±5G`，即有效窗口 `[995,1005]`。

### B.6 包Lane规则完整链路

涉及函数：`_validate_package_lane_rules`、`_validate_final_package_lanes`。

1. 前置判定是否包Lane上下文。
2. 执行三条硬校验：
   - Index对数总和>=5；
   - 最新Index规则无冲突；
   - 有效总量∈[999.99,1000.01]。
3. 中间过程允许失败分区，不直接并入普通池。
4. 最终解输出前执行包Lane强复核，失败直接报错阻断。

### B.7 10+24专项规则完整链路

涉及函数：`_validate_lane_seq_10_plus_24_rules`。

1. 从普通池剥离10+24文库，独立成组。
2. 组合时先看合同量，再叠加5%平衡量。
3. 有效总量必须进入[995,1005]。
4. 复核要求：Index对数>=5，且无最新Index冲突。

### B.8 AI Lane最小Index对数（`_validate_ai_lane_index_pair_rules`）

1. 仅在非包Lane + 3.6T-NEW场景生效。
2. 规则为：Lane总Index对数必须>=5。
3. 不满足时直接判该Lane不合法。

### B.9 最新Index规则覆盖逻辑（`_validate_lane_with_latest_index`）

1. 先执行原校验器拿到基础结果。
2. 再执行最新Index冲突检测。
3. 用最新结果覆盖原Index冲突字段。
4. 最终合并special split与57结果，形成统一Lane判定。

### B.10 57规则逻辑细化（`_validate_lane_57_mix_rules`）

1. 包Lane上下文直接跳过通用57约束。
2. 专用不均衡Lane：
   - 允许AI平衡文库；
   - 禁止原始非不均衡库混入。
3. 普通混排Lane必须通过兼容性检查。
4. 该规则与候选择优逻辑联动，优先达到35%不均衡目标。

### B.11 全局优先级硬约束（`_enforce_global_priority_hard_constraint`）

1. 当前放开档位由门禁函数解析，固定顺序：`P0 -> P1 -> P2`。
2. 档位定义：
   - `P0`：临检 / SJ；
   - `P1`：YC；
   - `P2`：其他。
3. 每条Lane若包含超出当前放开档位的低优文库，按以下顺序处理：
   - 先裁剪低优文库并重校验；
   - 仍失败则整条Lane回退；
   - 若“高优池无法重建合法Lane”则触发保护分支，跳过整Lane移除。
4. 与该收口步骤联动的池规模阈值：
   - 0 Lane 且未分配文库数 `>=300`，可跳过高成本救援；
   - 未分配文库数 `>=1500` 或未分配总量 `>=18000G`，可降配/跳过高成本救援；
   - 1.1 后置阈值：未分配文库数 `>=1000` 或未分配总量 `>=4000G`。

### B.12 客户占比/10bp占比自动矫正（`_auto_fix_lane_for_customer_and_10bp`，当前已启用）

### B.13 平衡文库注入链路（`_materialize_balance_libraries_for_solution`）

   - 混排不均衡目标占比：`35%`。
3. 注入失败时，按固定顺序兜底：
   - 裁剪可替换普通文库；
   - 从未分配池替换；
   - 跨Lane交换。
4. 所有兜底步骤均失败时，移除该Lane并回收原始文库。
5. 专用不均衡Lane保护策略：优先保留全量原始文库，避免通用裁剪误删。

### B.14 终态复核与清理（`_final_non_package_validation_cleanup`）

### C.23 失败处理标准动作库

1. **逐库回退**：用于候选构建阶段的快速失败（容量/Index/互斥）。
