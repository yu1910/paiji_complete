# 预测模型组合特征优化建议

创建时间：2026-05-08 16:38:42

更新时间：2026-06-10

## 一、背景

当前排机程序中，真正影响上机动作的是下单量 `lorderdata（下单量）`。产出量 `loutput（真实产出）` 是历史真实结果，可用于训练、统计、评估和风险分析，但不宜作为线上主决策链路中的二次预测目标。

业务上存在大量字段组合，例如文库类型、建库环节、库检结果、QPCR（定量聚合酶链式反应检测）、峰图、机型、测序模式、Lane 混排组成、Index（索引序列） 类型、碱基不均衡等。

这些组合数量非常大，历史数据不可能覆盖所有组合。因此，模型优化的重点不应只关注“模型参数量是否足够大”，而应关注特征表达、组合覆盖、低频组合回退、业务目标函数、Lane 归一化真实产率和验证方式。

需要特别注意：在没有真实按模型下单并上机的情况下，无法直接得到模型下单策略的真实产出。用“预测下单量”再输入“预测产出模型”得到的欠产率或浪费率，本质上是模型自评模型，会叠加误差，不能作为真实业务效果。

## 二、几个可行优化方案

### 方案一：下单量不要只预测绝对值，改成比例或候选档位

直接预测 `lorderdata（下单量）` 容易受合同量规模影响。更稳的方式是先表达为下单倍数，或进一步生成多个候选下单档位。

#### 1. 下单倍数

定义：
```
order_ratio（下单倍数） = lorderdata（下单量） / wkcontractdata（合同量）
```

预测后还原：
```
predicted_lorderdata（预测下单量） = wkcontractdata（合同量） * predicted_order_ratio（预测下单倍数）
```

#### 2. 历史效率

定义：
```
observed_efficiency（观测效率） = loutput（真实产出） / lorderdata（下单量）
```

历史效率不建议作为线上二次预测产出的主链路，而应主要用于组合统计、候选下单档位损失计算、低频组合回退和离线评估。

这种方式让模型或统计规则学习“下单倍数”和“历史效率分布”，比直接学习绝对值更容易泛化，尤其适合新合同量区间和新组合。

### 方案二：使用 CatBoost（类别提升模型） 处理高维类别组合

当前大量关键字段属于无序类别，例如：

- `wksampletype（文库类型）`
- `wkjkhj（文库建库环境）`
- `wkcomplexresult（库建综合结果）`
- `wkqpcr（QPCR定量检测）`
- `wkpeakmap（峰图）`
- `wkpeaksize（峰图主峰片段大小）`
- `wkxpd（小片段）`
- `wkqubit（接头比值）`
- `wkcontractdata（合同数据量）`
- `wk_jjbj（是否碱基不均）`
- 产品线
- 机型
- 测序模式

如果使用 XGBoost（极端梯度提升模型） 并通过 `LabelEncoder（标签编码器）` 编码类别，模型可能误以为类别之间存在大小顺序。对于这类场景，建议引入 CatBoost（类别提升模型） 作为对照模型、候选档位评分模型或残差修正模型。

CatBoost（类别提升模型） 的优势：

- 对类别特征支持更自然；
- 对高基数类别更友好；
- 对低频类别有平滑机制；
- 更适合学习类别组合；
- 在表格数据预测中表现稳定。

建议对比：

1. CatBoostRegressor（类别提升回归模型）；
2. LightGBM（轻量梯度提升模型，使用类别特征）；
3. XGBoost（极端梯度提升模型） 现有方案。

### 方案三：做分层回退，而不是让模型硬猜所有组合

低频组合不应完全依赖模型硬预测。建议建立组合支持度统计，并按历史样本量做分层回退。

可统计的组合层级：
```
L6 = wksampletype（文库类型） + wkjkhj（文库建库环境） + wkcomplexresult（库建综合结果） + wkqpcr（QPCR定量检测） + wkpeakmap（峰图） + wkpeaksize（峰图主峰片段大小） + wkxpd（小片段） + wkqubit（接头比值） + contract_bin（合同数据量分箱） + wk_jjbj（是否碱基不均）
L5 = wksampletype（文库类型） + wkjkhj（文库建库环境） + wkcomplexresult（库建综合结果） + wkqpcr（QPCR定量检测） + wkpeakmap（峰图） + wkpeaksize（峰图主峰片段大小） + wkxpd（小片段） + wkqubit（接头比值）
L4 = wksampletype（文库类型） + wkjkhj（文库建库环境） + wkcomplexresult（库建综合结果） + wkqpcr（QPCR定量检测） + wkpeakmap（峰图）
L3 = wksampletype（文库类型） + wkjkhj（文库建库环境） + wkcomplexresult（库建综合结果）
L2 = wksampletype（文库类型） + wkjkhj（文库建库环境）
L1 = wksampletype（文库类型）
L0 = 全局
```

预测时根据当前组合历史样本数决定使用细粒度修正还是上级回退：

- 完整组合样本量 ≥ 100：使用细粒度组合修正；
- 完整组合样本量 20 到 100：使用平滑修正；
- 完整组合样本量 < 20：回退到上一级组合；
- 文库类型本身也很少见：回退到文库大类或产出分组。

这种方式比单纯增大模型参数更可靠。

### 方案四：显式加入组合统计特征

不要完全依赖模型从零发现所有组合规律，可以将历史统计结果作为特征输入模型。

#### 1. 文库类型维度

- `sampletype_order_ratio_mean（文库类型下单倍数均值）`
- `sampletype_order_ratio_median（文库类型下单倍数中位数）`
- `sampletype_output_rate_mean（文库类型产出率均值）`
- `sampletype_shortage_rate（文库类型欠产率）`
- `sampletype_over_output_rate（文库类型超产率）`

#### 2. 文库类型 × 建库环节

- `sampletype_jkhj_order_ratio_mean（文库类型建库环节下单倍数均值）`
- `sampletype_jkhj_output_rate_mean（文库类型建库环节产出率均值）`
- `sampletype_jkhj_shortage_rate（文库类型建库环节欠产率）`

#### 3. 文库类型 × 建库环节 × 库检结果

- `sampletype_jkhj_complex_output_rate_mean（文库类型建库环节库检结果产出率均值）`
- `sampletype_jkhj_complex_shortage_rate（文库类型建库环节库检结果欠产率）`

#### 4. Lane 维度

- `lane_mix_output_rate_mean（Lane混排产出率均值）`
- `lane_sampletype_diversity（Lane文库类型多样性）`
- `lane_risky_type_ratio（Lane高风险类型占比）`
- `lane_low_output_type_ratio（Lane低产类型占比）`
- `lane_customer_built_ratio（Lane客户自建文库占比）`

注意：这些统计特征必须只用训练集计算，验证集、测试集和线上推理不能泄漏未来数据。

### 方案五：使用模型集成，但不要让单模型直接裁决最终下单量

建议构建多个模型并进行集成：

1. CatBoost（类别提升模型） 模型：主攻类别组合；
2. LightGBM（轻量梯度提升模型） / XGBoost（极端梯度提升模型） 模型：主攻数值特征和非线性关系；
3. 规则/统计模型：主攻低频组合、历史效率分布和业务兜底。

不建议简单做单点预测加权：
```
old_single_point_prediction（旧单点预测值） = 0.5 * CatBoost（类别提升模型） + 0.3 * LightGBM（轻量梯度提升模型）/XGBoost（极端梯度提升模型） + 0.2 * RuleBackoff（规则回退）
```

更建议把模型用于候选档位评分或残差修正：

```
candidate_score（候选评分） =
    统计损失
    + ML（机器学习）残差修正
    + 业务规则惩罚
```

并根据置信度动态调整机器学习残差权重：

- 高频组合：提高机器学习模型权重；
- 低频组合：提高统计回退和业务规则权重；
- 新组合：不使用或少使用机器学习残差，优先统计回退和业务规则。

### 方案六：增加置信度、支持度和真实产率解释

生产中不建议只输出单点预测值，还应输出：

- 最终下单量；
- 候选下单档位；
- 置信度；
- 是否低频组合；
- 是否新组合；
- 组合支持度；
- 使用的回退层级；
- 所在 Lane；
- 预测下单占比；
- 历史真实产率分布；
- 预测档位与真实产率 1 的距离；
- 是否远离历史可观测范围。

示例：
```
最终下单量：120G（数据量单位）

候选档位：100G（数据量单位） / 110G（数据量单位） / 120G（数据量单位） / 135G（数据量单位）

选中档位：120G（数据量单位）

组合历史样本数：48

回退层级：wksampletype（文库类型） + wkjkhj（文库建库环境） + wkcomplexresult（库建综合结果）

预测下单占比：12.0%

历史同组合真实产率 P50（第50百分位）：0.98

距离理想真实产率 1：0.02

置信度：中
```

这样即使模型遇到不熟悉的组合，也不会盲目输出一个看似精确但实际不可靠的数值。

### 方案七：线上主链路只决策下单量，不把产出预测作为二次裁决

上机动作最终只需要 `lorderdata（下单量）`。因此线上主链路应收敛为：

```
输入文库与 Lane 上下文
    ↓
输出最终 lorderdata（下单量）
```

历史真实 `loutput（真实产出）` 仍然非常重要，但它的作用应放在训练和评估阶段：

- 构造历史效率：`observed_efficiency（观测效率） = loutput（真实产出） / lorderdata（下单量）`；
- 标记历史欠产：`historical_shortage（历史欠产标记） = loutput（真实产出） < wkcontractdata（合同量）`；
- 统计不同组合的效率分布；
- 识别低产、高波动、高风险组合；
- 做模型离线评估和线上回放分析。

不建议把线上主链路做成：

```
预测下单量
    ↓
预测产出量
    ↓
根据预测产出再判断欠产或浪费
```

原因是第二步属于反事实产出预测：历史数据中通常只有“人工或旧策略下单量”对应的真实产出，没有“模型建议下单量”对应的真实产出。预测下单量的误差会传递给产出模型，产出模型自身误差又会继续叠加，最终得到的欠产率、浪费率不可信。

产出预测模型可以保留，但应作为辅助工具：

- 评估在历史真实下单量下，产出模型是否能拟合历史 `loutput（真实产出）`；
- 分析组合效率和异常样本；
- 生成参考解释，不作为最终下单裁决依据；
- 支持 shadow（影子模式） 模式对比，不直接闭环修正线上下单量。

### 方案八：从单文库独立预测改成 Lane 内候选档位联合选择

一个文库下单多了，首先会造成自身浪费；同时它在同一 Lane 中的下单占比变大，会影响其他文库的实际产出占比。因此下单量不应完全按单文库独立保守上调，而应在同一 Lane 内一起比较候选档位。

最终判断不使用“预测下单量 -> 预测产出量 -> 再计算欠产/浪费”的链路，而使用历史真实上机数据中的 Lane 归一化真实产率：

```
真实产率 = (真实产出 / 下单) / (Lane拆分产出 / Lane下单)
```

理想真实产率是 1：

- 接近 1：该文库下单占比与真实产出占比基本匹配；
- 明显小于 1：相对 Lane 平均水平，下单偏多或产出偏低；
- 明显大于 1：相对 Lane 平均水平，下单偏少或产出偏高；
- 评估目标不是越大越好，而是越接近 1 越好。

新的决策流程建议如下：

```
1. 每个文库生成多个候选下单档位
2. 每个候选档位估计真实产率接近 1 的可能性
3. 在同一 Lane 内联合选择候选档位
4. 输出每个文库最终 lorderdata（下单量）
```

历史回放示例：

```
某 Lane 真实拆分产出 = 130G（数据量单位）

历史下单：
A = 70G（数据量单位），真实产出 = 58G（数据量单位）
B = 40G（数据量单位），真实产出 = 42G（数据量单位）
C = 30G（数据量单位），真实产出 = 30G（数据量单位）
Lane历史下单 = 140G（数据量单位）

Lane平均产率 = 130 / 140 = 0.929

A历史真实产率 = (58 / 70) / 0.929 = 0.89
B历史真实产率 = (42 / 40) / 0.929 = 1.13
C历史真实产率 = (30 / 30) / 0.929 = 1.08
```

如果模型候选改成：

```
A = 65G（数据量单位）
B = 45G（数据量单位）
C = 30G（数据量单位）
Lane预测下单 = 140G（数据量单位）
```

则用同一批真实产出回放：

```
A预测下单真实产率 = (58 / 65) / (130 / 140) = 0.96
B预测下单真实产率 = (42 / 45) / (130 / 140) = 1.01
C预测下单真实产率 = (30 / 30) / (130 / 140) = 1.08
```

这个候选组合比历史下单更好，因为 A 和 B 都更接近 1，C 没有变差。这里没有预测产出，真实产出来自历史上机结果；离线评估只是在比较“如果当时这样下单，真实产率会不会更接近 1”。

候选档位的损失函数可以定义为：

```
loss（损失） = 真实产率偏离惩罚 + 浪费惩罚 + 欠产风险惩罚 + 偏离历史合理范围惩罚
```

其中：

- 真实产率偏离惩罚来自 `abs（绝对值函数）(candidate_real_rate（候选真实产率） - 1)`；
- 浪费惩罚来自候选下单量明显高于历史合理区间或合同安全区间；
- 欠产风险惩罚来自历史效率低分位、组合历史欠产情况和业务硬规则；
- 偏离历史合理范围惩罚用于限制候选档位离历史可观测范围太远。

可用算法：

- 每个 Lane 内候选数量较少时：枚举所有候选组合；
- 候选数量较多时：贪心替换或 beam search（束搜索）；
- 需要严格找最优时：整数规划；
- 实时要求高时：先用贪心策略落地，再用离线回放对比。

## 三、真正应该担心的不是参数量，而是这几个问题

### 问题一：类别编码方式是否合理

如果 XGBoost（极端梯度提升模型） 使用 `LabelEncoder（标签编码器）` 编码类别，会让模型误以为类别有大小顺序。

例如：
```
ATAC-seq（转座酶可及染色质测序）文库 = 1

RNA（核糖核酸）文库 = 2

10X（十倍单细胞平台）文库 = 3
```

模型可能错误理解为 `3 > 2 > 1` 存在业务含义。

对于无序类别，更建议尝试：

- CatBoost（类别提升模型） 原生类别处理；
- LightGBM（轻量梯度提升模型） categorical feature（类别特征）；
- 目标编码；
- 分层平滑编码；
- 类别归并和标准化。

### 问题二：验证方式是否真实

如果使用随机划分训练集和测试集，可能会高估模型效果。生产预测面对的是未来数据，因此建议采用时间切分。

示例：
```
前几个月训练

后一个月验证

最新一个月测试
```

这样更接近真实上线场景，也更容易发现模型随时间漂移的问题。

### 问题三：是否按组合维度评估

只看整体 MAE（平均绝对误差）、RMSE（均方根误差） 或 R2（决定系数） 不够。整体指标好，不代表关键业务组合预测准确。

建议按以下维度分别评估：

- 每个文库类型的误差；
- 每个建库环节的误差；
- 每个机型的误差；
- 每个测序模式的误差；
- 高频组合误差；
- 低频组合误差；
- 新组合误差；
- 历史欠产组合识别能力；
- Lane 内候选档位选择是否让真实产率接近 1；
- overlap replay（重叠样本回放） 样本中的真实表现。

如果担心组合学不到，就必须专门做组合维度评估，而不能只看整体平均误差。

### 问题四：目标函数是否符合业务

普通回归模型通常优化 MSE（均方误差） 或 MAE（平均绝对误差），会倾向预测平均值。但业务中预测偏低和预测偏高的代价并不对称。

- 预测低了：可能欠产，影响交付；
- 预测高了：可能浪费产能，但有时比欠产代价小。

因此建议考虑：

- 候选下单档位损失函数；
- Lane 内候选档位联合选择；
- 低频组合回退；
- 欠产和浪费的非对称损失；
- 偏离历史可观测范围惩罚。

模型目标应与业务目标一致，而不是只追求平均误差最低。

## 四、更新后的推荐方案

如果目标是上线可用的下单决策，不建议继续把主链路设计成“预测下单量 + 预测产出量 + 欠产风险分类器修正”。更合适的方向是：

```
历史真实效率分布
+
组合分层回退
+
候选下单档位
+
Lane 内候选档位联合选择
+
ML（机器学习） 残差小幅修正
+
业务上下限保护
```

推荐的生产架构：

```
原始输入与排机结果
    ↓
构造文库、组合、Lane 上下文
    ↓
按组合层级读取历史效率分布与支持度
    ↓
为每个文库生成候选下单档位
    ↓
计算每个候选档位的业务损失
    ↓
在同一 Lane 内联合选择候选档位
    ↓
输出最终 lorderdata（下单量）
    ↓
输出解释字段：回退层级、支持度、候选档位、真实产率距离、置信度
```

### 1. 线上主输出只保留下单量

线上用于上机的主输出应是：

```
lorderdata（下单量）
```

`lai_output（预测产出字段）` 或预测产出可以保留为参考字段，但不应作为最终下单量的二次裁决依据。

### 2. 下单不再按单文库独立保守上调

单文库独立保守上调会增加浪费，也会改变同一 Lane 内其他文库的产出占比。一个文库下单多了，不能只看它自己是否欠产，还要看同一 Lane 内各文库的真实产率是否整体更接近 1。

因此最终下单量建议在 Lane 内联合选择：

```
lane_key（Lane标识） = lrunid（上机批次编号） + llaneid（Lane编号） / lane_unique_id（Lane唯一编号）
```

在每个 `lane_key（Lane标识）` 内求解：

```
minimize sum（求和函数）(loss_i（第i个文库损失）(order_i（第i个文库下单量）))

满足条件：
    min_order_i（第i个文库最低下单量） <= order_i（第i个文库下单量） <= max_order_i（第i个文库最高下单量）
    abs（绝对值函数）(lane_normalized_real_rate_i（第i个文库Lane归一化真实产率）(order_i（第i个文库下单量）) - 1) 尽量小
```

### 3. 候选档位来自历史效率分布，而不是单点预测

每个文库先生成有限个候选下单档位，例如：

```
contract（合同量） = 50G（数据量单位）

候选下单档位：
50G（数据量单位）, 55G（数据量单位）, 60G（数据量单位）, 65G（数据量单位）, 70G（数据量单位）, 80G（数据量单位）
```

候选档位可以来自：

- 合同量倍数；
- 历史人工下单倍数分位数；
- 组合历史效率低分位反推；
- 当前业务上下限；
- 特殊规则，如加测、低起始量、客户自建、高风险峰图。

### 4. 业务损失函数要同时惩罚欠产和浪费

单纯压低欠产会导致过量下单，单纯压低浪费又会提高欠产。建议为每个候选档位计算综合损失：

```
loss（损失） = rate_deviation_loss（真实产率偏离损失） + shortage_loss（欠产损失） + waste_loss（浪费损失） + out_of_support_loss（超出历史支持范围损失）
```

其中：

```
rate_deviation_loss（真实产率偏离损失）:
    候选下单量对应的 Lane 归一化真实产率偏离 1 的惩罚

shortage_loss（欠产损失）:
    候选下单量在历史效率低分位下仍可能不足的惩罚

waste_loss（浪费损失）:
    预期产出或下单量明显高于合同安全区间的惩罚

out_of_support_loss（超出历史支持范围损失）:
    候选下单量远离历史可观测范围、组合样本过少或新组合的惩罚
```

### 5. ML（机器学习） 模型降级为残差修正，不做最终裁决

机器学习模型仍然有价值，但不建议让它直接决定最终下单量。更稳的方式是：

```
final_order_candidate_score（最终下单候选评分） =
    统计损失
    + ML（机器学习） 残差修正
    + 业务规则惩罚
```

ML（机器学习） 只做小幅修正：

```
ml_residual（机器学习残差） = clip（截断函数）(model_residual（模型残差）, -residual_cap（残差上限）, +residual_cap（残差上限）)
```

并且根据组合支持度调整权重：

```
高频组合：residual_weight（残差权重） = 1.0
中频组合：residual_weight（残差权重） = 0.4 - 0.7
低频组合：residual_weight（残差权重） = 0.0 - 0.3
新组合：不使用 ML（机器学习） 残差，只用统计回退和业务规则
```

### 6. CatBoost（类别提升模型） 可以做对照，但不是核心答案

CatBoost（类别提升模型） 对高维类别更友好，值得作为候选模型加入实验。但如果组合回退、候选档位、真实产率目标和业务损失函数没有处理好，单纯换模型无法解决真实问题。

建议优先级：

1. 先完成 Lane 内候选档位联合选择框架；
2. 再做组合统计和候选档位损失；
3. 然后比较 XGBoost（极端梯度提升模型）、CatBoost（类别提升模型）、LightGBM（轻量梯度提升模型） 的残差修正效果；
4. 最后再决定是否替换主模型。

## 五、数据处理流程建议

整体流程建议如下：

```
原始历史数据
    ↓
字段标准化、单位统一、去重
    ↓
剔除明显脏数据
    ↓
保留真实好结果和真实坏结果
    ↓
标记异常业务场景
    ↓
构造历史事实字段：
    - observed_order_ratio（观测下单倍数） = lorderdata（下单量） / wkcontractdata（合同量）
    - observed_efficiency（观测效率） = loutput（真实产出） / lorderdata（下单量）
    - observed_output_ratio（观测产出倍数） = loutput（真实产出） / wkcontractdata（合同量）
    - historical_shortage（历史欠产标记） = loutput（真实产出） < wkcontractdata（合同量）
    ↓
构造组合统计：
    - 组合历史效率 P10（第10百分位） / P15（第15百分位） / P25（第25百分位） / P50（第50百分位）
    - 组合历史下单倍数 P25（第25百分位） / P50（第50百分位） / P75（第75百分位）
    - 组合支持度
    - 组合波动程度
    - 组合历史欠产率
    ↓
构造 Lane 上下文：
    - lane_current_order_sum（Lane当前下单总量）
    - lane_current_contract_sum（Lane当前合同量总和）
    - group_library_count（组内文库数量）
    - group_risky_type_ratio（组内高风险类型占比）
    - group_low_efficiency_type_ratio（组内低效率类型占比）
    ↓
为每个文库生成候选下单档位
    ↓
为每个候选档位计算损失
    ↓
时间切分训练/验证/测试
    ↓
训练 ML（机器学习） 残差模型或候选档位排序模型
    ↓
Lane 内候选档位联合选择
    ↓
按组合维度、Lane 维度、时间维度评估
```

### 1. 原始历史数据处理

原始历史数据需要先完成字段标准化、单位统一和去重，确保训练输入口径一致。对于合同量、下单量、产出量、QPCR（定量聚合酶链式反应检测）、峰图、小片段、接头比、LaneID（测序通道编号） 等关键字段，要统一数值单位和缺失值处理方式。

### 2. 剔除明显脏数据

需要剔除的是脏数据，而不是产出不好的数据。明显脏数据包括：

- 合同量为空或小于等于 0；
- 下单量为空或小于等于 0；
- 产出量为空或明显不可信；
- 单位错误；
- 重复记录；
- 关键字段错位；
- 不可能的极端数值；
- Lane 归属明显错误；
- 目标字段口径与当前业务不一致且无法修正的数据。

### 3. 保留真实好结果和真实坏结果

真实产出好的数据和真实产出不够好的数据都要保留。

好数据用于学习：

- 哪些文库类型稳定高产；
- 哪些建库环节比较安全；
- 哪些 QPCR（定量聚合酶链式反应检测） 区间表现好；
- 哪些 Lane 组合产出稳定；
- 哪些场景可以降低过量下单，减少产能浪费。

坏数据用于学习：

- 哪些组合容易欠产；
- 哪些文库类型低产；
- 哪些客户自建文库风险高；
- 哪些 QPCR（定量聚合酶链式反应检测）、峰图、小片段、接头比组合需要补偿；
- 哪些 Lane 混排结构不稳定；
- 哪些场景下历史下单量不够。

不能因为产出不够好就删除样本，否则模型会误以为所有组合都安全，线上容易欠产。

### 4. 标记异常业务场景

对于异常但有真实业务原因的数据，不建议直接删除，应尽量保留并打标。例如：

- 机器故障；
- 特殊补测；
- 客户特殊要求；
- 人工临时调整；
- 污染风险；
- 样本质量异常；
- 重测或补测流程；
- Lane 混排或上机批次异常；
- 临时人工改 pooling 或改下单。

如果系统中没有明确字段，可以考虑从备注字段中抽取结构化标记。异常业务数据如果不打标直接训练，模型可能把异常当成普通规律学习。

### 5. 不再把欠产风险分类器作为主决策

`historical_shortage（历史欠产标记） = loutput（真实产出） < wkcontractdata（合同量）` 是历史下单量下的结果，不是文库天然风险。同一个文库在不同下单量下可能从欠产变成不欠产。

因此不建议把主链路设计成：

```
预测欠产概率
    ↓
根据概率上调下单量
```

更建议把候选下单量显式放入决策：

```
candidate_order（候选下单量）
    ↓
计算该候选档位的损失
    ↓
Lane 内候选档位联合选择
```

这样风险和下单量是绑定评估的，不会让一个欠产分类器单独承担最终决策。

### 6. 时间切分训练、验证和测试

训练、验证、测试建议按时间切分，而不是随机切分。生产预测面对的是未来数据，时间切分更接近真实上线场景。

示例：

```
前几个月训练
后一个月验证
最新一个月测试
```

随机切分、Lane 均衡切分、文库类型均衡切分可以作为诊断，但不能替代时间切分。

### 7. 离线评估要区分真实可评估和反事实不可评估

在没有真实按模型下单并上机前，不能直接计算模型下单策略的真实欠产率和真实浪费率。

可以做的评估包括：

```
1. factual output error（事实产出误差）
   用历史真实下单量预测产出，和真实 loutput（真实产出） 对比。

2. overlap replay（重叠样本回放）
   只评估模型建议下单量与历史真实下单量接近的样本。
   例如 abs（绝对值函数）(pred_order / historical_order - 1) <= 5% 或 10%。

3. proxy target error（代理目标误差）
   用历史效率反推代理最优下单量，再比较模型输出。
   该指标依赖效率不随下单量大幅变化的假设，只能作为参考。

4. out-of-support report（超出历史支持范围报告）
   标记模型建议下单量远离历史范围、组合支持度低、新组合的样本。
```

必须避免把下面的指标当成真实业务效果：

```
预测下单量
    ↓
预测产出量
    ↓
计算欠产率 / 浪费率
```

这类指标只能作为模型内部参考，不能作为上线效果结论。

### 8. 按组合和 Lane 维度评估

上线前需要按以下维度分别评估：

- 高频组合；
- 低频组合；
- 新组合；
- 高风险文库类型；
- 客户自建文库；
- 碱基不均衡文库；
- 不同机型和测序模式；
- 不同 Lane 混排结构；
- 模型下单量与历史下单量接近的 overlap 样本；
- 模型下单量远离历史范围的 out-of-support 样本；
- Lane 内各文库真实产率是否更接近 1。

## 六、最终结论

1. 上机主动作只需要 `lorderdata（下单量）`，因此线上主链路应以最终下单量为核心。
2. 产出预测不是没有价值，但不应作为“预测下单后再预测产出再修正下单”的主链路。
3. 没有真实按模型下单并上机，就无法直接计算真实欠产率和真实浪费率，只能做离线近似评估和风险分层。
4. 下单量不是单文库独立预测问题，而是同一 Lane 内候选档位联合选择问题。
5. 单文库过度保守会增加浪费，也可能改变同一 Lane 内其他文库的产出占比。
6. 更合适的生产方案是：

```
历史效率分布
+
组合分层回退
+
候选下单档位
+
候选档位损失函数
+
Lane 内候选档位联合选择
+
ML（机器学习） 残差小幅修正
+
业务上下限保护
```

7. 机器学习模型应优先用于残差修正、候选档位排序、异常识别和文本字段结构化，不应单独承担最终下单裁决。
8. CatBoost（类别提升模型）、LightGBM（轻量梯度提升模型）、XGBoost（极端梯度提升模型） 都可以比较，但模型选择排在真实产率目标、组合回退和业务损失函数之后。

最终建议：

```
保留真实好数据和真实坏数据
剔除明显脏数据
对异常业务场景打标
统计历史效率分布和组合支持度
生成候选下单档位
在同一 Lane 内联合选择候选档位
输出最终 lorderdata（下单量）、回退层级、真实产率距离和置信度
```

这比单纯追求模型参数量、单独预测欠产风险、或串联预测下单与产出更符合实际上机决策。





## 七、模型迭代方案

前面的内容保留为背景和备选思路。最终建议把主方案收敛为“真实产率监督学习”，不再把候选档位优化器作为主链路。

说明：

lorderdata（下单量） 不适合作为最终监督学习目标本身，因为它确实是人工经验系数算出来的，模型直接学它，本质是在复制旧经验。旧经验如果偏保守、偏浪费、对低频组合不准，模型也会学进去。

但 lorderdata（下单量） 仍然必须参与训练标签构造。原因是：

真实产出 只有在某个历史下单量下发生。没有历史下单量，就没法判断这个产出是“下单多导致浪费”，还是“下单少但产出高”，也没法算：

真实产率 = (真实产出 / 下单) / (Lane拆分产出 / Lane下单)

所以结论是：

不学人工下单量本身；
用人工下单量作为历史实验条件；
用真实产出反推这个历史下单是否偏多或偏少；
学习修正后的目标，比如 real_rate（真实产率） 或 ideal_order_ratio（理想下单倍数）


### 1. 最终目标

线上主输出仍然只保留：

```
lorderdata（下单量）
```

`loutput（真实产出）` 只在历史训练和离线评估中使用，不在线上预测时作为输入，也不再做“预测下单量 -> 预测产出量 -> 再修正下单量”的链路。

最终方案名称：

```
基于 Lane 归一化真实产率的下单倍数模型
```

核心链路：

```
历史真实上机数据
    ↓
计算真实产率、理想下单量、理想下单倍数
    ↓
构造文库特征、Lane 特征、组合历史统计特征
    ↓
训练监督学习模型
    ↓
预测 ideal_order_ratio（理想下单倍数）
    ↓
final_lorderdata（最终下单量） = wkcontractdata（合同量） * ideal_order_ratio（理想下单倍数）
    ↓
业务上下限保护和低支持度回退
```

### 2. 训练标签

先按 Lane 汇总历史真实数据：

```
lane_output（Lane真实拆分产出） = sum（求和函数）(loutput（真实产出）)
lane_order（Lane真实下单总量） = sum（求和函数）(lorderdata（下单量）)
lane_efficiency（Lane平均效率） = lane_output（Lane真实拆分产出） / lane_order（Lane真实下单总量）
```

再对每个文库计算真实产率：

```
real_rate（真实产率） =
    (loutput（真实产出） / lorderdata（下单量）)
    /
    (lane_output（Lane真实拆分产出） / lane_order（Lane真实下单总量）)
```

这个 `real_rate（真实产率）` 是核心学习字段。它在线上不能直接得到，所以样本级 `real_rate（真实产率）` 是训练标签，不是线上输入特征。

由真实产率反推历史样本的理想下单量：

```
ideal_order（理想下单量） = lorderdata（下单量） * real_rate（真实产率）
ideal_order_ratio（理想下单倍数） = ideal_order（理想下单量） / wkcontractdata（合同量）
```

解释：

```
real_rate（真实产率） > 1：历史下单相对偏少，理想下单量应上调
real_rate（真实产率） < 1：历史下单相对偏多，理想下单量应下调
real_rate（真实产率） = 1：历史下单占比与真实产出占比匹配
```

最终模型建议直接学习 `ideal_order_ratio（理想下单倍数）`，或者学习 `log_ideal_order_ratio（理想下单倍数对数）`。其中 `real_rate（真实产率）` 同时作为解释字段和组合统计字段。

### 3. 特征字段

样本基础特征：

```
文库类型(wksampletype) --- 20%
      		文库建库环境(wkjkhj)：客户自建/诺禾手工/诺禾自动 -- 10%
      			库建综合结果(wkcomplexresult) --6% （合格/不合格/风险）
        			qpcr(wkqpcr) --- 13%
        			峰图(wkpeakmap) --- 6%
            				peaksize(wkpeaksize) --- 6%
            				小片段(wkxpd)  --- 6%
            				接头比值(wkqubit) --- 6%
    合同数据量(wkcontractdata)：22%
    是否碱基不均(wk_jjbj) --- 5%
```

Lane 特征：

```
Lane内文库数
Lane内合同量总和
Lane内文库类型数量
Lane内高风险文库占比
Lane内客户自建文库占比
当前文库合同量 / Lane合同量总和
```

组合历史统计特征：

```
real_rate_p25（真实产率第25百分位）
real_rate_p50（真实产率第50百分位）
real_rate_p75（真实产率第75百分位）
ideal_order_ratio_p25（理想下单倍数第25百分位）
ideal_order_ratio_p50（理想下单倍数第50百分位）
ideal_order_ratio_p75（理想下单倍数第75百分位）
observed_order_ratio_p50（历史实际下单倍数第50百分位）
support_count（支持样本数）
rate_std（真实产率标准差）
historical_shortage_rate（历史欠产率）
```

### 3.1 历史比例和CV特征使用

`合同/下单`、`合同/产出`、`产出/下单` 这三个比例需要统计历史数据，但不作为训练目标。它们更适合作为组合历史统计特征，帮助模型理解某类组合过去的人工下单经验、欠产风险和产出效率。

先在历史样本中计算三个基础比例：

```
contract_order_ratio（合同下单比） = wkcontractdata（合同量） / lorderdata（下单量）
contract_output_ratio（合同产出比） = wkcontractdata（合同量） / loutput（真实产出）
output_order_ratio（产出下单比） = loutput（真实产出） / lorderdata（下单量）
```

再按推荐历史层级 L6 到 L0 分组统计：

```
contract_order_ratio_p50（合同下单比第50百分位）
contract_order_ratio_cv（合同下单比变异系数）

contract_output_ratio_p50（合同产出比第50百分位）
contract_output_ratio_cv（合同产出比变异系数）

output_order_ratio_p50（产出下单比第50百分位）
output_order_ratio_cv（产出下单比变异系数）
```

其中：

```
CV（变异系数） = std（标准差函数） / mean（平均函数）
```

使用方式：

```
1. 训练集内，按时间窗口和推荐层级统计这些历史比例特征
2. 给每条训练样本拼接其所属组合在过去窗口中的统计值
3. 验证集、测试集和线上预测时，只能使用预测时间点之前的历史统计
4. 如果当前组合在 L6 样本数不足，则回退到 L5、L4、L3，直到样本数足够
5. 这些比例特征作为模型输入，训练目标仍然是 log_ideal_order_ratio（理想下单倍数对数）
```

第一版不建议把所有分位数都加入模型，避免特征过多。建议先使用 `P50（第50百分位） + CV（变异系数） + support_count（支持样本数）`。如果后续发现某些组合波动大，再补充 `P25（第25百分位）` 和 `P75（第75百分位）`。

注意：`contract_output_ratio（合同产出比）` 和 `output_order_ratio（产出下单比）` 都包含 `loutput（真实产出）`。它们只能来自历史统计，不能用当前待预测样本自己的真实产出计算，否则会造成数据泄漏。

组合统计特征必须只用训练窗口内的历史数据计算。验证集、测试集和线上预测不能使用未来数据，否则会产生数据泄漏。

### 4. 历史统计层级是否有必要

有必要，而且这是关键特征。

模型不可能凭单条样本把所有高维组合学准。历史统计层级的作用是把“这个组合过去真实产率怎样、波动多大、样本数够不够”显式告诉模型。

推荐层级：

```
L6 = wksampletype（文库类型） + wkjkhj（文库建库环境） + wkcomplexresult（库建综合结果） + wkqpcr（QPCR定量检测） + wkpeakmap（峰图） + wkpeaksize（峰图主峰片段大小） + wkxpd（小片段） + wkqubit（接头比值） + contract_bin（合同数据量分箱） + wk_jjbj（是否碱基不均）
L5 = wksampletype（文库类型） + wkjkhj（文库建库环境） + wkcomplexresult（库建综合结果） + wkqpcr（QPCR定量检测） + wkpeakmap（峰图） + wkpeaksize（峰图主峰片段大小） + wkxpd（小片段） + wkqubit（接头比值）
L4 = wksampletype（文库类型） + wkjkhj（文库建库环境） + wkcomplexresult（库建综合结果） + wkqpcr（QPCR定量检测） + wkpeakmap（峰图）
L3 = wksampletype（文库类型） + wkjkhj（文库建库环境） + wkcomplexresult（库建综合结果）
L2 = wksampletype（文库类型） + wkjkhj（文库建库环境）
L1 = wksampletype（文库类型）
L0 = 全局
```



### 5. 模型选择

首选：

```
CatBoostRegressor（类别提升回归模型）
```

原因：

- 类别字段多；
- 组合特征多；
- 低频类别需要平滑；
- 不需要把类别强行做 `LabelEncoder（标签编码器）` 顺序编码；
- 比现有 XGBoost（极端梯度提升模型） 更适合这类高维类别组合。

对照模型：

```
XGBoost（极端梯度提升模型）作为baseline基线模型
```

第一版不要做复杂模型融合。先用一个主模型 + 历史统计回退，把目标定义和评估口径跑通。

### 6. 训练目标

```
target（训练目标） = log_ideal_order_ratio（理想下单倍数对数）
log_ideal_order_ratio（理想下单倍数对数） = log（对数函数）(ideal_order_ratio（理想下单倍数）)
```

使用对数目标有两个好处：

- 上调和下调更对称；
- 极端大值对模型影响更小。

预测后还原：

```
pred_ideal_order_ratio（预测理想下单倍数） = exp（指数函数）(model_output（模型输出）)
pred_lorderdata（预测下单量） = wkcontractdata（合同量） * pred_ideal_order_ratio（预测理想下单倍数）
```

### 7. 数据处理

必须保留真实好结果和真实坏结果。不能因为产出差就删除，否则模型学不到哪些组合真实产率偏离 1。

需要剔除或单独标记的数据：

```
合同量为空或小于等于 0
下单量为空或小于等于 0
真实产出为空或明显不可信
Lane归属缺失或明显错误
单位错误
重复记录
机器故障、补测、污染、人工异常调整等异常场景
```

异常场景不要一律删除。能解释的异常应打标；无法解释且明显不属于正常生产规律的样本再剔除。

标签截尾建议：

```
real_rate（真实产率） 按 P1（第1百分位） 到 P99（第99百分位） 截尾
ideal_order_ratio（理想下单倍数） 按 P1（第1百分位） 到 P99（第99百分位） 截尾
```

### 8. 线上预测

```
输入当前文库和 Lane 特征
读取当前组合的历史统计特征
CatBoostRegressor（类别提升回归模型） 输出 pred_ideal_order_ratio（预测理想下单倍数）
计算 pred_lorderdata（预测下单量）
按业务上下限裁剪
低支持度组合回退到父层级统计下单倍数
输出 final_lorderdata（最终下单量）
```

业务保护：

```
final_lorderdata（最终下单量）不能小于业务最低下单量
final_lorderdata（最终下单量）不能大于历史同组合合理上限
低支持度或新组合降低模型权重，优先使用父层级统计值
```



## 八、评估方案

评估方案改为使用真实历史上机数据验证，不再使用“预测下单量 -> 预测产出量 -> 计算欠产率/浪费率”的链路。

核心思想：

```
用真实产出不变
把历史真实下单替换成模型预测下单
计算 Lane 归一化后的真实产率变化
```

### 1. 核心公式

（真实产出/下单）/（lane拆分产出/lane下单）=真实产率

对每个文库 `i`，属于 Lane `g`：

```
真实产出 = real_output_i（第i个文库真实产出）
预测下单 = pred_order_i（第i个文库预测下单量）
真实Lane拆分产出 = real_lane_output_g（第g个Lane真实拆分产出）
Lane预测下单 = pred_lane_order_g（第g个Lane预测下单总量）
```

其中：

```
pred_lane_order_g（第g个Lane预测下单总量） = sum（求和函数）(pred_order_i（第i个文库预测下单量） for i in lane g)
```

按预测下单替换后的真实产率定义为：

```
pred_replaced_real_rate_i（第i个文库预测下单替换后的真实产率） =
    (真实产出 / 预测下单)
    /
    (真实Lane拆分产出 / Lane预测下单)
```

也就是：

```
pred_replaced_real_rate_i（第i个文库预测下单替换后的真实产率） =
    (real_output_i（第i个文库真实产出） / pred_order_i（第i个文库预测下单量）)
    /
    (real_lane_output_g（第g个Lane真实拆分产出） / pred_lane_order_g（第g个Lane预测下单总量）)
```

等价理解：

```
pred_replaced_real_rate_i（第i个文库预测下单替换后的真实产率） =
    文库真实产出占比 / 文库预测下单占比
```

即：

```
pred_replaced_real_rate_i（第i个文库预测下单替换后的真实产率） =
    (real_output_i（第i个文库真实产出） / real_lane_output_g（第g个Lane真实拆分产出）)
    /
    (pred_order_i（第i个文库预测下单量） / pred_lane_order_g（第g个Lane预测下单总量）)
```

这个指标表示：在真实 Lane 产出已知的情况下，如果把下单量替换成模型预测下单量，该文库相对 Lane 平均水平的真实产率是多少。

理想值是：

```
pred_replaced_real_rate_i（第i个文库预测下单替换后的真实产率） = 1
```

### 2. 历史真实产率基准

为了判断模型是否优于历史下单，需要同时计算历史真实下单口径下的真实产率。

历史字段：

```
历史真实下单 = historical_order_i（第i个文库历史真实下单量）
Lane历史真实下单 = historical_lane_order_g（第g个Lane历史真实下单总量）
```

其中：

```
historical_lane_order_g（第g个Lane历史真实下单总量） = sum（求和函数）(historical_order_i（第i个文库历史真实下单量） for i in lane g)
```

历史真实产率：

```
historical_real_rate_i（第i个文库历史真实产率） =
    (真实产出 / 历史真实下单)
    /
    (真实Lane拆分产出 / Lane历史真实下单)
```

即：

```
historical_real_rate_i（第i个文库历史真实产率） =
    (real_output_i（第i个文库真实产出） / historical_order_i（第i个文库历史真实下单量）)
    /
    (real_lane_output_g（第g个Lane真实拆分产出） / historical_lane_order_g（第g个Lane历史真实下单总量）)
```

### 3. 模型达标判断

按该评估口径，核心判断不是 `pred_replaced_real_rate_i（第i个文库预测下单替换后的真实产率）` 越大越好，而是离 1 越近越好。

```
pred_rate_error_i（第i个文库预测真实产率误差） = abs（绝对值函数）(pred_replaced_real_rate_i（第i个文库预测下单替换后的真实产率） - 1)
historical_rate_error_i（第i个文库历史真实产率误差） = abs（绝对值函数）(historical_real_rate_i（第i个文库历史真实产率） - 1)
```

如果满足：

```
pred_rate_error_i（第i个文库预测真实产率误差） <= historical_rate_error_i（第i个文库历史真实产率误差）
```

说明在真实历史产出不变的前提下，把历史下单替换成预测下单后，该文库的 Lane 归一化真实产率更接近 1，模型达到该样本的目标要求。

样本级结果：

```
rate_pass_i（第i个文库真实产率通过标记） = pred_rate_error_i（第i个文库预测真实产率误差） <= historical_rate_error_i（第i个文库历史真实产率误差）
```

差值：

```
rate_error_delta_i（第i个文库真实产率误差差值） = pred_rate_error_i（第i个文库预测真实产率误差） - historical_rate_error_i（第i个文库历史真实产率误差）
```

其中：

```
rate_error_delta_i（第i个文库真实产率误差差值） < 0：预测下单更接近理想真实产率 1
rate_error_delta_i（第i个文库真实产率误差差值） = 0：与历史下单持平
rate_error_delta_i（第i个文库真实产率误差差值） > 0：预测下单比历史下单更偏离 1
```

### 4. 必须同时保留的保护条件

该指标不能单独使用。因为如果模型把 `pred_order_i（第i个文库预测下单量）` 压得过低，`real_output_i（第i个文库真实产出） / pred_order_i（第i个文库预测下单量）` 会变大，可能导致产率指标虚高。

因此样本达标必须同时满足：

```
pred_rate_error_i（第i个文库预测真实产率误差） <= historical_rate_error_i（第i个文库历史真实产率误差）
pred_order_i（第i个文库预测下单量） >= min_order_i（第i个文库最低下单量）
pred_order_i（第i个文库预测下单量） <= max_order_i（第i个文库最高下单量）
pred_order_i（第i个文库预测下单量） 不明显远离历史同组合可观测范围
```

其中：

```
min_order_i（第i个文库最低下单量） = 业务允许的最低下单量
max_order_i（第i个文库最高下单量） = 业务允许的最高下单量
```

最终样本通过条件：

```
sample_pass_i（第i个样本通过标记） =
    rate_pass_i（第i个文库真实产率通过标记）
    and order_lower_bound_pass_i（第i个文库下限通过标记）
    and order_upper_bound_pass_i（第i个文库上限通过标记）
    and in_support_range_i（第i个文库在历史支持范围内标记）
```

### 5. Lane 级评估

每个 Lane 需要汇总：

```
pred_lane_order_g（第g个Lane预测下单总量） = sum（求和函数）(pred_order_i（第i个文库预测下单量）)
historical_lane_order_g（第g个Lane历史真实下单总量） = sum（求和函数）(historical_order_i（第i个文库历史真实下单量）)
real_lane_output_g（第g个Lane真实拆分产出） = sum（求和函数）(real_output_i（第i个文库真实产出）) 或真实Lane拆分产出
```

Lane 级评估不再额外引入下单变化比例、P95（第95百分位） 或多套误差指标。仍然只看同一个真实产率目标：该 Lane 内文库在预测下单替换后，真实产率是否更接近 1。

```
lane_real_rate_better_ratio_g（第g个Lane真实产率更优比例） =
    mean（平均函数）(real_rate_better_i（第i个文库真实产率更优标记） for i in Lane g)
```

### 6. 汇总指标

整体评估只围绕真实产率，不再同时输出多套误差指标。核心就是比较“历史下单下的真实产率”和“预测下单替换后的真实产率”谁更接近 1。

```
historical_real_rate_i（第i个文库历史真实产率）
pred_replaced_real_rate_i（第i个文库预测下单替换后的真实产率）
```

真实产率偏离 1 的距离：

```
historical_real_rate_gap_i（第i个文库历史真实产率偏离） =
    abs（绝对值函数）(historical_real_rate_i（第i个文库历史真实产率） - 1)

pred_real_rate_gap_i（第i个文库预测替换真实产率偏离） =
    abs（绝对值函数）(pred_replaced_real_rate_i（第i个文库预测下单替换后的真实产率） - 1)
```

单个文库是否变好：

```
real_rate_better_i（第i个文库真实产率更优标记） =
    pred_real_rate_gap_i（第i个文库预测替换真实产率偏离）
    <= historical_real_rate_gap_i（第i个文库历史真实产率偏离）
```

整体只汇总一个主指标：

```
real_rate_better_ratio（真实产率更优比例） =
    mean（平均函数）(real_rate_better_i（第i个文库真实产率更优标记）)
```

分层评估也只看同一个指标 `real_rate_better_ratio（真实产率更优比例）`，不再新增其他指标：

```
按 wksampletype（文库类型） 分组
按 wkjkhj（文库建库环境） 分组
按 wkcomplexresult（库建综合结果） 分组
按 wkqpcr（QPCR定量检测） 分组
按 wkpeakmap（峰图） 分组
按 wkpeaksize（峰图主峰片段大小） 分组
按 wkxpd（小片段） 分组
按 wkqubit（接头比值） 分组
按 contract_bin（合同数据量分箱） 分组
按 wk_jjbj（是否碱基不均） 分组
按 Lane 分组
按高频 / 中频 / 低频 / 新组合分组
```

### 7. 通过标准

第一版建议通过标准：

```
real_rate_better_ratio（真实产率更优比例） 达到业务设定阈值
各关键分层的 real_rate_better_ratio（真实产率更优比例） 不明显低于整体
预测下单替换后的真实产率整体更接近 1
低频组合和新组合不能出现大面积真实产率远离 1
```

下单上下限、历史合理范围和异常样本过滤属于业务保护条件，仍然要保留，但不作为本节的主评估指标。主评估指标只看真实产率是否更接近 1。
