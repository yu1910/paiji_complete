# 预测模型组合特征优化建议

创建时间：2026-05-08 16:38:42

更新时间：2026-05-08 17:38:09

## 一、背景

当前排机程序中，下单量和产出预测属于典型的结构化表格数值预测问题。业务上存在大量字段组合，例如文库类型、建库环节、库检结果、QPCR、峰图、机型、测序模式、Lane 混排组成、Index 类型、碱基不均衡等。

这些组合数量非常大，历史数据不可能覆盖所有组合。因此，模型优化的重点不应只关注“模型参数量是否足够大”，而应关注特征表达、组合覆盖、低频组合回退、业务目标函数和验证方式。

## 二、几个可行优化方案

### 方案一：不要只预测绝对值，改成预测比例

直接预测 `lorderdata` 和 `lai_output` 容易受合同量规模影响。更稳的方式是预测比例。

#### 1. 下单倍数

定义：
```text
order_ratio = lorderdata / wkcontractdata
```

预测后还原：
```text
predicted_lorderdata = wkcontractdata * predicted_order_ratio
```

#### 2. 产出率

定义：
```text
output_rate = loutput / lorderdata
```

预测后还原：
```text
predicted_output = predicted_lorderdata * predicted_output_rate
```

这种方式让模型学习“倍数”和“效率”，比直接学习绝对值更容易泛化，尤其适合新合同量区间和新组合。

### 方案二：使用 CatBoost 处理高维类别组合

当前大量关键字段属于无序类别，例如：

- `wksampletype`
- `wkjkhj`
- `wkcomplexresult`
- `wkpeakmap`
- 产品线
- 机型
- 测序模式

如果使用 XGBoost 并通过 `LabelEncoder` 编码类别，模型可能误以为类别之间存在大小顺序。对于这类场景，建议引入 CatBoost 作为主模型或对照模型。

CatBoost 的优势：

- 对类别特征支持更自然；
- 对高基数类别更友好；
- 对低频类别有平滑机制；
- 更适合学习类别组合；
- 在表格数据预测中表现稳定。

建议对比：

1. CatBoostRegressor；
2. LightGBM with categorical features；
3. XGBoost 现有方案。

### 方案三：做分层回退，而不是让模型硬猜所有组合

低频组合不应完全依赖模型硬预测。建议建立组合支持度统计，并按历史样本量做分层回退。

可统计的组合层级：
```text
wksampletype

wksampletype + wkjkhj

wksampletype + wkjkhj + wkcomplexresult

wksampletype + wkjkhj + wkcomplexresult + wkpeakmap

wksampletype + wkjkhj + 机型 + 测序模式
```

预测时根据当前组合历史样本数决定使用细粒度修正还是上级回退：

- 完整组合样本量 ≥ 100：使用细粒度组合修正；
- 完整组合样本量 20 到 100：使用平滑修正；
- 完整组合样本量 < 20：回退到上一级组合；
- 文库类型本身也很少见：回退到文库大类或产出分组。

这种方式比单纯增大模型参数更可靠。

### 方案四：显式加入组合统计特征

不要完全依赖模型从零发现所有组合规律，可以将历史统计结果作为特征输入模型。

#### 1. 文库类型维度

- `sampletype_order_ratio_mean`
- `sampletype_order_ratio_median`
- `sampletype_output_rate_mean`
- `sampletype_shortage_rate`
- `sampletype_over_output_rate`

#### 2. 文库类型 × 建库环节

- `sampletype_jkhj_order_ratio_mean`
- `sampletype_jkhj_output_rate_mean`
- `sampletype_jkhj_shortage_rate`

#### 3. 文库类型 × 建库环节 × 库检结果

- `sampletype_jkhj_complex_output_rate_mean`
- `sampletype_jkhj_complex_shortage_rate`

#### 4. Lane 维度

- `lane_mix_output_rate_mean`
- `lane_sampletype_diversity`
- `lane_risky_type_ratio`
- `lane_low_output_type_ratio`
- `lane_customer_built_ratio`

注意：这些统计特征必须只用训练集计算，验证集、测试集和线上推理不能泄漏未来数据。

### 方案五：使用模型集成，不要押宝单模型

建议构建多个模型并进行集成：

1. CatBoost 模型：主攻类别组合；
2. LightGBM / XGBoost 模型：主攻数值特征和非线性关系；
3. 规则/统计模型：主攻低频组合和业务兜底。

融合方式示例：
```text
final_prediction = 0.5 * CatBoost + 0.3 * LightGBM/XGBoost + 0.2 * RuleBackoff
```

也可以根据置信度动态加权：

- 高频组合：提高机器学习模型权重；
- 低频组合：提高统计回退和业务规则权重；
- 新组合：使用保守策略和预测区间。

### 方案六：增加置信度和风险控制

生产中不建议只输出单点预测值，还应输出：

- 预测值；
- 预测区间；
- 置信度；
- 是否低频组合；
- 是否新组合；
- 欠产风险概率；
- 是否建议保守上调。

示例：
```text
预测下单量：120G

P10：105G

P50：120G

P90：145G

欠产风险：高

组合历史样本数：8

建议：使用 P75 或 P90 作为下单量
```

这样即使模型遇到不熟悉的组合，也不会盲目输出一个看似精确但实际不可靠的数值。

## 三、真正应该担心的不是参数量，而是这几个问题

### 问题一：类别编码方式是否合理

如果 XGBoost 使用 `LabelEncoder` 编码类别，会让模型误以为类别有大小顺序。

例如：
```text
ATAC-seq文库 = 1

RNA文库 = 2

10X文库 = 3
```

模型可能错误理解为 `3 > 2 > 1` 存在业务含义。

对于无序类别，更建议尝试：

- CatBoost 原生类别处理；
- LightGBM categorical feature；
- 目标编码；
- 分层平滑编码；
- 类别归并和标准化。

### 问题二：验证方式是否真实

如果使用随机划分训练集和测试集，可能会高估模型效果。生产预测面对的是未来数据，因此建议采用时间切分。

示例：
```text
前几个月训练

后一个月验证

最新一个月测试
```

这样更接近真实上线场景，也更容易发现模型随时间漂移的问题。

### 问题三：是否按组合维度评估

只看整体 MAE、RMSE 或 R2 不够。整体指标好，不代表关键业务组合预测准确。

建议按以下维度分别评估：

- 每个文库类型的误差；
- 每个建库环节的误差；
- 每个机型的误差；
- 每个测序模式的误差；
- 高频组合误差；
- 低频组合误差；
- 新组合误差；
- 欠产样本召回率；
- 过量下单浪费率。

如果担心组合学不到，就必须专门做组合维度评估，而不能只看整体平均误差。

### 问题四：目标函数是否符合业务

普通回归模型通常优化 MSE 或 MAE，会倾向预测平均值。但业务中预测偏低和预测偏高的代价并不对称。

- 预测低了：可能欠产，影响交付；
- 预测高了：可能浪费产能，但有时比欠产代价小。

因此建议考虑：

- 欠产加权损失；
- Quantile Regression；
- P75 / P80 保守预测；
- 欠产概率模型；
- 下单量保守上调策略。

模型目标应与业务目标一致，而不是只追求平均误差最低。

## 四、我的建议

如果目标是让模型真正学习复杂组合规律，不建议把核心数值预测切换为大语言模型。更合理的方向是升级机器学习预测体系。

建议如下：

1. 保留机器学习作为核心预测模型；
2. 增加 CatBoost，与现有 XGBoost 对比；
3. 将目标改成下单倍数和产出率，而不是只预测绝对值；
4. 加入组合统计特征和分层回退特征；
5. 建立低频组合检测；
6. 输出置信度和预测区间；
7. 按组合维度做验证报告；
8. 大语言模型只用于备注解析、文库类型归一化、异常解释等辅助场景。

推荐的生产架构：
```text
机器学习模型预测主数值
+
组合统计模型兜底
+
业务规则保守修正
+
大语言模型辅助文本特征和解释
```

最终判断：

- 机器学习不可能学到所有组合；
- 大语言模型也不能凭参数量解决真实标签不足的问题；
- 对结构化数值预测，历史数据质量、特征设计、组合回退和业务目标函数比参数体量更关键；
- 最优方案是机器学习主导预测，大语言模型辅助文本理解和解释。

## 五、数据处理流程建议

整体流程建议如下：
```text
原始历史数据
    ↓
字段标准化、单位统一、去重
    ↓
剔除明显脏数据
    ↓
保留真实好结果和真实坏结果
    ↓
标记异常业务场景
    ↓
构造目标：
    - order_ratio
    - output_rate
    - is_shortage
    ↓
构造组合统计特征：
    - 文库类型历史产出率
    - 文库类型 × 建库环节欠产率
    - 文库类型 × 合同量区间下单倍数
    - Lane 混排风险特征
    ↓
时间切分训练/验证/测试
    ↓
训练：
    - 回归模型
    - 分位数模型
    - 欠产分类模型
    ↓
按组合维度评估
    ↓
上线时输出预测值、置信度、欠产风险、回退层级
```

### 1. 原始历史数据处理

原始历史数据需要先完成字段标准化、单位统一和去重，确保训练输入口径一致。对于合同量、下单量、产出量、QPCR、峰图、小片段、接头比等关键字段，要统一数值单位和缺失值处理方式。

### 2. 剔除明显脏数据

需要剔除的是脏数据，而不是产出不好的数据。明显脏数据包括：

- 合同量为空或小于等于 0；
- 下单量为空或小于等于 0；
- 产出量为空或明显不可信；
- 单位错误；
- 重复记录；
- 关键字段错位；
- 不可能的极端数值；
- 目标字段口径与当前业务不一致且无法修正的数据。

### 3. 保留真实好结果和真实坏结果

真实产出好的数据和真实产出不够好的数据都要保留。

好数据用于学习：

- 哪些文库类型稳定高产；
- 哪些建库环节比较安全；
- 哪些 QPCR 区间表现好；
- 哪些 Lane 组合产出稳定；
- 哪些场景可以降低过量下单，减少产能浪费。

坏数据用于学习：

- 哪些组合容易欠产；
- 哪些文库类型低产；
- 哪些客户自建文库风险高；
- 哪些 QPCR、峰图、小片段、接头比组合需要补偿；
- 哪些 Lane 混排结构不稳定；
- 哪些场景下历史下单量不够。

不能因为产出不够好就删除样本，否则模型会误以为所有组合都安全，线上容易欠产。

### 4. 标记异常业务场景

对于异常但有真实业务原因的数据，不建议直接删除，应尽量保留并打标。例如：

- 机器故障；
- 特殊补测；
- 客户特殊要求；
- 人工临时调整；
- 污染风险；
- 样本质量异常；
- 重测或补测流程。

如果系统中没有明确字段，可以考虑从备注字段中抽取结构化标记。异常业务数据如果不打标直接训练，模型可能把异常当成普通规律学习。

### 5. 构造多个训练目标

建议不要只训练一个回归目标，而是至少构造三个目标：
```text
order_ratio = lorderdata / wkcontractdata
output_rate = loutput / lorderdata
is_shortage = loutput < wkcontractdata
```

对应模型：

- 下单倍数模型：学习历史下单策略；
- 产出率模型：学习真实测序产出效率；
- 欠产风险模型：判断当前组合是否高风险。

最终决策可以采用：
```text
预测下单量 = 合同量 × 预测下单倍数

如果欠产风险高：
    使用 P75 / P80 / P90 分位数下单倍数
否则：
    使用 P50 或略保守倍数
```

### 6. 时间切分训练、验证和测试

训练、验证、测试建议按时间切分，而不是随机切分。生产预测面对的是未来数据，时间切分更接近真实上线场景。

示例：
```text
前几个月训练
后一个月验证
最新一个月测试
```

### 7. 按组合维度评估

上线前需要按组合维度评估，而不仅仅看整体 MAE、RMSE 或 R2。重点评估：

- 高频组合；
- 低频组合；
- 新组合；
- 高风险文库类型；
- 客户自建文库；
- 碱基不均衡文库；
- 不同机型和测序模式；
- 欠产召回率；
- 过量下单浪费率。

## 六、最终结论

1. 历史数据足够多时，机器学习可以学得很准确，尤其是高频组合。
2. 如果想每个细粒度组合都单独学准，数据需求会非常大，可能需要几百万条以上有效样本。
3. 实际生产不应该要求模型学完所有组合，而应该采用：
```text
主模型学习整体规律
+
组合统计特征学习历史偏差
+
分层回退处理低频组合
+
欠产风险模型做保守修正
```

4. 产出好的数据和产出不好的数据都要保留。
5. 不能删除真实坏结果，否则模型学不到风险。
6. 应该删除的是脏数据，不是坏结果数据。
7. 好数据用于学习正常规律和避免浪费，坏数据用于学习风险和避免欠产。
8. 如果坏样本少，要采用加权训练、单独欠产分类器、分位数模型或保守策略。

最终建议：
```text
保留真实好数据和真实坏数据
剔除明显脏数据
对异常业务场景打标
用比例目标建模
增加欠产风险模型
按组合支持度做分层回退
```

这比单纯追求模型参数量更有效，也更符合排机预测的业务特点。
